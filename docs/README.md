## 🧭 Как пользоваться волтом

1. **Одна сущность — одна заметка.** ADR, задача, баг, хвост, вопрос — отдельные файлы. Связи между ними — wikilinks, поэтому граф и панель «Обратные ссылки» показывают реальную картину: какой вопрос блокирует какую задачу и какое решение её породило.
2. **Короткие ссылки работают через алиасы.** У каждой заметки в frontmatter есть `aliases: [TASK-001]`, поэтому пишем `[[TASK-001]]`, а не полное имя файла.
3. **Индексы не заполняются руками** — там Dataview-запросы по тегам и полям frontmatter. Достаточно правильно оформить frontmatter новой заметки.
4. **Нумерация папок задаёт порядок** в боковой панели, от требований к журналам.

## 🏷️ Система тегов

| Ось | Теги |
|---|---|
| Тип | `#adr` `#task` `#bug` `#debt` `#question` `#spec` `#log` `#meta` |
| Статус | `#status/open` `#status/planned` `#status/in-progress` `#status/blocked` `#status/done` `#status/accepted` `#status/fixed` `#status/answered` |
| Приоритет | `#p0` `#p1` `#p2` `#p3` |
| Область | `#area/security` `#area/compliance` `#area/delivery` `#area/design` `#area/stream` `#area/trading` `#area/platform` `#area/process` |
| Этап | `#stage/pre-M0` `#stage/M0` … `#stage/M6` |

> [!danger] Правила регулируемого домена
> Проект обслуживает регулируемый финансовый бизнес: ошибка публикации — это претензия регулятора, а не битая вёрстка.
> - Любое решение по **комплаенсу, выдаче наружу, изоляции тенантов или доступу** оформляется ADR обязательно, даже если кажется мелким.
> - Баг с утечкой черновика / чужого тенанта / невалидной по схеме выдачи — автоматически `#p0`.
> - Хвост в безопасности или комплаенсе — не ниже `#p1`, и не закрывается «живём с этим» без явного согласия заказчика.
> - Отступление от разд. 6 и 13 ТЗ запрещено; при необходимости — это вопрос заказчику, а не решение разработчика.
