# BUG-003 — Сгенерированный откат миграции не работает

> [!bug] Карточка
> **Статус:** 🟢 fixed `2026-07-31` · **Приоритет:** p2
> **Где:** `down` в миграциях, генерируемых `payload migrate:create`
> **Не наш код:** дефект генератора Payload

## Симптом

`pnpm run migrate:down` падает и откатывает сам себя:

```
Error migrating down 20260730_222321_add_audit_events. Rolling back.
caused by: error: constraint "payload_locked_documents_rels_audit_events_fk"
of relation "payload_locked_documents_rels" does not exist
```

Таблица при этом остаётся на месте — откат не выполнен.

## Воспроизведение

1. Создать коллекцию, сгенерировать миграцию.
2. Применить её.
3. `pnpm run migrate:down`.

**Окружение:** Payload 3.86.0, `@payloadcms/db-postgres`, Postgres 16.

## Причина

Генератор выстраивает операции в порядке:

```sql
DROP TABLE "audit_events" CASCADE;
ALTER TABLE "payload_locked_documents_rels"
  DROP CONSTRAINT "payload_locked_documents_rels_audit_events_fk";
```

`CASCADE` уже удаляет внешний ключ вместе с таблицей, на которую он ссылается. Следующая строка пытается удалить то, чего больше нет, — и падает.

Порядок неверен по существу: связи должны сниматься **до** таблицы, а не после.

## Исправление

Порядок в `down` переписан вручную: сначала триггеры (иначе удаление упрётся в защиту самого журнала), затем внешний ключ, индекс и колонка, и только потом таблица и тип. Добавлены `IF EXISTS` — откат должен быть выполним и после частичного применения.

## Урок

> [!important] Сгенерированный `down` не проверяется генератором
> Он выглядит правдоподобно и не исполняется до тех пор, пока откат кому-нибудь не понадобится — то есть в самый неудачный момент.
>
> ТЗ разд. 11 требует отката за секунды, но речь там о **релизах контента**, а не о схеме: откат схемы в проде — редкая и осознанная операция. Тем не менее миграция, чей `down` не работает, — это миграция без пути назад, и знать об этом лучше заранее.

## Регресс-тест

Автотеста нет: прогон `down` требует применённой миграции и разрушает базу, что несовместимо с быстрым набором. Проверка ручная — при добавлении миграции с внешними ключами прогнать `migrate:down` и `migrate` в тестовой базе.

Записано в [[Конвенции разработки]] как шаг при создании миграции.
