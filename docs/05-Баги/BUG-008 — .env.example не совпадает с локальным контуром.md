# BUG-008 — `.env.example` не совпадает с локальным контуром

> [!bug] Карточка
> **Статус:** fixed · **Приоритет:** p2 · **Где:** `.env.example`, `README.md` (раздел «Быстрый старт»)
> **Связано:** [[TASK-010]]

## Симптом

Быстрый старт из README выполнен буквально на чистой машине:

```bash
pnpm install
docker compose -f docker-compose.dev.yml up -d
cp .env.example .env
pnpm run migrate
```

Последняя команда падает: `password authentication failed for user "cms"` (SQLSTATE `28P01`), после чего процесс умирает необработанным отказом промиса. На машине, где порт `5432` свободен, отказ был бы другим — `ECONNREFUSED`, — но результат тот же: миграции не накатываются.

## Воспроизведение

1. Пустая машина, контейнеры подняты `docker-compose.dev.yml`.
2. `cp .env.example .env`.
3. `pnpm run migrate`.

**Окружение:** локальный контур · **Данные:** не нужны · **Частота:** всегда.

## Ожидалось

README утверждает прямо: «`cp .env.example .env` — значения уже совпадают с compose». Значит, установка обязана работать без правки файла.

## Причина

`.env.example` описывал **стандартные** порты, а compose намеренно смещает их (комментарий в самом compose объясняет, почему):

| Переменная | Было в `.env.example` | Даёт compose |
|---|---|---|
| `DATABASE_URL` | `localhost:5432`, пароль `CHANGE_ME` | `5433`, `dev_only_not_a_secret` |
| `REDIS_URL` | `localhost:6379` | `6380` |
| `BUS_URL` | `localhost:5672`, `CHANGE_ME` | `5673`, `dev_only_not_a_secret` |
| `S3_ACCESS_KEY_ID` | `CHANGE_ME` | `cms_dev_access_key` |
| `S3_SECRET_ACCESS_KEY` | `CHANGE_ME_…` | `dev_only_not_a_secret_32_chars_min` |
| `MEDIA_PUBLIC_URL` | `localhost:9001` | раздача MinIO — `9000`, `9001` это веб-консоль |

Секреты приложения (`PAYLOAD_SECRET`, `PREVIEW_SECRET`, `DELIVERY_KEY_PEPPER`) стояли заглушками `CHANGE_ME_…` длиной ровно под предел — то есть валидацию проходили, но осмысленного значения не имели.

Расхождение накопилось незаметно: `.env.example` написан на M0 ([[TASK-005]]), смещение портов появилось позже вместе с compose, и с тех пор никто не разворачивал репозиторий с нуля — на машине разработки `.env` уже лежал.

> [!note] Признак этого класса дефектов
> Документ, обещающий работающую установку, проверяется только установкой с нуля. Всё остальное время он верен по инерции: у того, кто его правит, окружение уже поднято.

## Исправление

`.env.example` приведён к compose: рабочие значения локального контура, включая смещённые порты. Шапка файла переписана — раньше она говорила «файл не содержит настоящих значений», теперь объясняет, что значения рабочие и почему это не секреты (контур живёт на машине разработчика и наружу не смотрит; настоящие секреты вне репозитория, ТЗ разд. 6).

`MEDIA_PUBLIC_URL` указывает на `9000` — порт раздачи, а не консоли. Пояснение добавлено рядом с переменной: на `9001` файлы не отдаются, и правило «отдельный origin» соблюдалось бы формально при неработающей раздаче.

## Регресс-теста нет, и это осознанно

Автотест здесь означал бы поднятие compose в CI и сверку с ним — то есть второй контур ради проверки первого. Дешевле и честнее — периодическая установка с нуля; она же поймала этот дефект.

**Проверено вживую `2026-09-03`:** `docker compose down -v` (тома стёрты, БД пуста — 0 таблиц) → `up -d` → `cp .env.example .env` → `pnpm run migrate` → 21 миграция, 45 таблиц. Затем `pnpm run migrate:test` и `pnpm run test:integration` — 200 тестов зелёные на тех же значениях.
