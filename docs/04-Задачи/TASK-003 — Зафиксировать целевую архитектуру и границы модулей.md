# TASK-003 — Зафиксировать целевую архитектуру и границы модулей

> [!info] Карточка
> **Статус:** 🟠 in-progress · **Приоритет:** p1 · **Этап:** M0
> **Пункт ТЗ:** 9 (стек и структура), 3 (принципы) · **Связано:** [[Архитектура]], [[ADR-0003]], [[ADR-0007]]

## Описание

Описать в [[Архитектура]]: четыре модуля (`stream`, `design`, `delivery`, `trading`), `platform/`, `contracts/`, публичный интерфейс каждого модуля и правило непересечения границ. Зафиксировать конкретные версии стека отдельным ADR.

Отдельно спроектировать то, что дороже всего менять позже:
- модель релиза и структуру снапшота;
- ключ кеша и правила инвалидации по тегам;
- кортеж разрешённых измерений из [[ADR-0003]];
- схему аудита (append-only на уровне БД).

## Критерий готовности

- [x] Для каждого модуля создан `index.ts` — публичный интерфейс с описанием зоны ответственности и границ.
- [x] Правило границ **принуждается технически**: ESLint `no-restricted-imports` по зонам ([[ADR-0007]]). Нарушение падает в CI.
- [x] Правила границ покрыты тестами (`src/platform/architecture.test.ts`) — ослабление конфигурации ловится.
- [x] Направление зависимостей зафиксировано: `modules → platform`, `delivery → modules`, `platform → ничего`.
- [x] Версии Payload / Next / React зафиксированы — [[ADR-0008]].
- [x] Модель тенантов, семантика наследования и изоляция — [[ADR-0010]], 78 тестов.
- [x] Наследование подключено к реальным полям тенанта — [[ADR-0013]]; юрисдикция, локали и локаль по умолчанию разрешаются по цепочке, проверено сквозь базу.
- [x] Схема аудита, append-only на уровне БД — [[ADR-0014]], проверено попытками изменить журнал напрямую в базе.
- [x] Модель релиза, каналы и откат — [[ADR-0015]]; иммутабельность проверена попытками правки напрямую в базе.
- [x] Ключ кеша и `ETag` — [[ADR-0015]]; все пять измерений из [[ADR-0003]] плюс версия формата.
- [ ] Правила инвалидации по тегам — вместе с outbox на M1.
