# TASK-006 — Отключить нативные REST и GraphQL Payload

> [!info] Карточка
> **Статус:** 🟠 in-progress · **Приоритет:** p1 · **Этап:** M0
> **Пункт ТЗ:** 13 (анти-требования), 6, разд. 3 · **Решение:** [[ADR-0009]]

## Описание

Payload поднимает собственные REST- и GraphQL-поверхности над всеми коллекциями. ТЗ прямо запрещает оставлять их как вторую дверь к данным: единственный выход наружу — версионированный API доставки, каждый ответ которого валидируется JSON Schema.

Задача заводится **на M0, а не позже**, потому что после появления данных незакрытая поверхность — это не техдолг, а действующий канал утечки черновиков и данных чужих тенантов.

## Критерий готовности

- [x] GraphQL и playground отключены полностью — `graphQL: { disable: true }`, корректность опции подтверждена типами.
- [x] Учётные записи людей не являются ключами API — `useAPIKey: false`.
- [x] **Статическая инвентаризация маршрутов**: список разрешённых HTTP-поверхностей объявлен явно и сверяется тестом в обе стороны — незадекларированный файл роняет CI, устаревшая запись в списке тоже.
- [ ] Нативный REST недоступен снаружи периметра — решается при монтировании админки ([[ADR-0009]], [[Q-005]]).
- [ ] Рантайм-проверка: обращение к нативным путям Payload из внешнего контура возвращает 404/403, а не данные. Требует поднятого приложения — этап M1.

> [!warning] Что закрыто, а что нет
> Закрыто: GraphQL и невозможность **незаметного** появления новой поверхности.
> Не закрыто: ограничение периметра для админки и фактическая проверка по живому серверу. Статическая инвентаризация видит файлы, но не видит маршрутов, создаваемых фреймворком программно — это ограничение проговорено в [[ADR-0009]], а не подразумевается.

> [!danger] Регуляторный смысл
> Закрывает критерий приёмки «Черновик невозможно получить через выдачу ни одним способом» — частично: со стороны GraphQL полностью, со стороны REST — после ограничения периметра.
