# TASK-006 — Отключить нативные REST и GraphQL Payload

> [!info] Карточка
> **Статус:** 🟠 in-progress · **Приоритет:** p1 · **Этап:** M0
> **Пункт ТЗ:** 13 (анти-требования), 6, разд. 3 · **Решение:** [[ADR-0009]]

## Описание

Payload поднимает собственные REST- и GraphQL-поверхности над всеми коллекциями. ТЗ прямо запрещает оставлять их как вторую дверь к данным: единственный выход наружу — версионированный API доставки, каждый ответ которого валидируется JSON Schema.

Задача заводится **на M0, а не позже**, потому что после появления данных незакрытая поверхность — это не техдолг, а действующий канал утечки черновиков и данных чужих тенантов.

## Критерий готовности

- [x] GraphQL и playground отключены полностью — `graphQL: { disable: true }`, корректность опции подтверждена типами.
- [x] Учётные записи людей не являются ключами API — `useAPIKey: false`.
- [x] **Статическая инвентаризация маршрутов**: список разрешённых HTTP-поверхностей объявлен явно и сверяется тестом в обе стороны — незадекларированный файл роняет CI, устаревшая запись в списке тоже.
- [x] **Рантайм-проверка на работающем приложении** `2026-07-31`: `POST /api/graphql` → 404, `GET /api/graphql-playground` → 404, `GET /api/tenants` и `/api/users` анонимно → 403.
- [x] Заголовки безопасности задаются приложением, не только прокси; `X-Powered-By` отсутствует.
- [x] Тест: среди маршрутов и в списке разрешённых нет ничего, похожего на graphql.
- [ ] Нативный REST недоступен снаружи периметра — **инфраструктурная часть**, зависит от [[Q-005]] (обратного прокси не существует).

> [!success] Что закрыто
> GraphQL отсутствует физически, а не отключён настройкой — маршрута нет, ответ 404.
> Служебный REST не является дырой: к нему применяется та же модель прав, что и везде ([[ADR-0012]]) — анонимный запрос получает 403. Отдельной модели доступа у него нет.
> Новая HTTP-поверхность не может появиться незаметно.

> [!warning] Что осталось
> Ограничение периметра для админки — работа на стороне инфраструктуры, а не приложения. Пока прокси нет, админка доступна там же, где приложение. Для тестового контура это приемлемо, для продового — нет.
> Статическая инвентаризация видит файлы, но не видит маршрутов, создаваемых фреймворком программно. Рантайм-проверка выше частично закрывает и это, но не автоматизирована — она выполнена руками.
