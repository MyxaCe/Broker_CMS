# TASK-006 — Отключить нативные REST и GraphQL Payload

> [!info] Карточка
> **Статус:** 🔵 planned · **Приоритет:** p1 · **Этап:** M0
> **Пункт ТЗ:** 13 (анти-требования), 6 («отключено всё лишнее»), разд. 3 («одна дверь наружу»)

## Описание

Payload поднимает собственные REST- и GraphQL-поверхности над всеми коллекциями. ТЗ прямо запрещает оставлять их как вторую дверь к данным: единственный выход наружу — версионированный API доставки, каждый ответ которого валидируется JSON Schema.

Задача заводится **на M0, а не позже**, потому что после появления данных незакрытая поверхность — это не техдолг, а действующий канал утечки черновиков и данных чужих тенантов.

## Критерий готовности

- [ ] GraphQL и playground отключены полностью.
- [ ] Нативный REST либо отключён, либо недоступен снаружи периметра — с явным обоснованием в ADR, если полностью отключить нельзя.
- [ ] Автотест: обращение к нативным путям Payload из внешнего контура возвращает 404/403, а не данные.
- [ ] Автотест перечисляет **все** зарегистрированные HTTP-маршруты приложения и падает при появлении незадекларированного — чтобы новая поверхность не появилась случайно при обновлении.

> [!danger] Регуляторный смысл
> Закрывает критерий приёмки «Черновик невозможно получить через выдачу ни одним способом».
