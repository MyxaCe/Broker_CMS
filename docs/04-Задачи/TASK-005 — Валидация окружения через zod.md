# TASK-005 — Валидация окружения через zod (fail-closed)

> [!warning] Карточка
> **Статус:** 🟣 review — реализовано, **но ни разу не прогнано** ([[Q-007]])
> **Приоритет:** p0 · **Этап:** M0 · **Пункт ТЗ:** 6.1, разд. 3

## Описание

Схема окружения на zod: отсутствие **или пустое значение** любого секрета — процесс не поднимается. Конструкции вида `if (key && ...)` запрещены: они превращают отсутствующий секрет в отключённую проверку, что и есть основной дефект предыдущей версии, названный в ТЗ.

Схема — единственная точка чтения `process.env` во всём приложении. Прямое обращение к `process.env` за пределами модуля конфигурации запрещается линт-правилом.

## Что сделано

`src/platform/config/env.ts` — единственная точка чтения `process.env`. Схема на zod, 19 переменных. `bootstrap.ts` завершает процесс с кодом 1 и читаемым списком проблем до поднятия сервера.

Две проверки предметной области, вытекающие прямо из решений:
- **`TRADING_TERMS_MODE` без умолчания** — невозможно случайно оказаться в ослабленном режиме `unverified` ([[ADR-0005]]).
- **`MEDIA_PUBLIC_URL` обязан отличаться по origin от `APP_PUBLIC_URL`** — совпадение означает XSS через загрузку файла (ТЗ 5.3).

## Критерий готовности

- [x] Отсутствие обязательной переменной → отказ старта со списком **всех** проблем разом, а не первой.
- [x] Пустая строка и строка из пробелов трактуются как отсутствие значения.
- [x] Секрет короче 32 символов отвергается.
- [x] Секреты не попадают в сводку конфигурации (`describeEnv`) — проверено отдельным тестом.
- [x] Линт-правило запрещает `process.env` вне модуля конфигурации; покрыто тестом в `architecture.test.ts`.
- [x] Ни одного условного использования секрета: конструкция `if (SECRET) { проверить }` в коде отсутствует по построению — секрет либо есть, либо процесс не стартовал.
- [ ] **Тесты прогнаны и зелёные** — блокировано [[Q-007]].
