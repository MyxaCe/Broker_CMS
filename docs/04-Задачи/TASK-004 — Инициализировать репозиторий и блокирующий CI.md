# TASK-004 — Инициализировать репозиторий и блокирующий CI

> [!info] Карточка
> **Статус:** 🟠 in-progress · **Приоритет:** p1 · **Этап:** M0
> **Пункт ТЗ:** 8 (тестирование и CI), 9 · **Связано:** [[Q-007]], [[DEBT-001]], [[ADR-0007]]

## Описание

`git init`, структура каталогов по [[Архитектура#2. Структура модулей (ТЗ разд. 9)]], `.gitignore`, линтер, форматтер, typecheck, аудит зависимостей — **всё блокирующее с самого начала**. ТЗ требует, чтобы CI блокировал мёрж при падении любой проверки; вводить это «когда будет что проверять» поздно — правило перестаёт соблюдаться в первый же спорный момент.

Сюда же: Renovate/Dependabot и запрет мажорных апдейтов без прогона контрактных тестов (ТЗ 6).

## Критерий готовности

- [x] Структура каталогов соответствует ТЗ разд. 9.
- [x] Конфигурация инструментов: `package.json`, строгий `tsconfig.json`, `eslint.config.mjs`, `.prettierrc.json`, `vitest.config.ts`.
- [x] `.gitignore` исключает `.env` и любые секреты (ТЗ разд. 6).
- [x] CI-воркфлоу написан и **падает** при ошибке линтера, формата, типов, теста или аудита зависимостей.
- [x] Автоматический апдейтер (`renovate.json`) с запретом автомёржа мажоров без контрактных тестов.
- [ ] `git init` — **невозможно**, git на машине отсутствует ([[Q-007]]).
- [ ] `pnpm install` и коммит lock-файла — **невозможно**, нет Node и pnpm ([[DEBT-001]]).
- [ ] CI прогнан хотя бы раз и подтверждён зелёным/красным по существу.
- [ ] Документирован в [[Конвенции разработки]] формат веток, коммитов и чек-лист ревью.

## Открытые зависимости
