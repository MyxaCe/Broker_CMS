# TASK-012 — Гейт не отдаёт чистый отчёт, не выполнившись

> [!info] Карточка
> **Статус:** done · **Приоритет:** p0 · **Этап:** M3
> **Пункт ТЗ:** 2.4, 3.2 · **Задача штаба:** CMS-05 · **Основание:** [[TASK-011]]

## Описание

Сверка M3 нашла два комплаенс-ограничителя, которые не выполняются и при этом **отдают чистый отчёт релиза**. Штаб выставил порядок: сначала сделать так, чтобы гейт не мог доложить об успехе, не выполнившись, и только потом достраивать сами правила. Обоснование: пока гейт умеет молча врать, починка правил увеличивает доверие к тому же документу, а не уменьшает риск.

## Сделано

### 1. Охват проверки — [[ADR-0029]]

`Validator` обязан объявлять `coverage(input)`: `checked` (осмотрено N единиц), `empty` (материала нет по-настоящему), `missing` (материал не передан). `missing` даёт блокирующую находку `check-not-executed` с формулировкой «результат проверки неизвестен, а не „нарушений нет“».

Метод обязательный: компилятор перечислил все семь существующих валидаторов за один прогон.

Убраны умолчания, скрывавшие непереданный материал: `texts` в `composeSnapshot` больше не имеет `?? []`, у ретрансляторов появилось поле `examined`.

### 2. Стоп-словарь получил тексты — [[DEBT-013]] погашен

`blocks/collect-text.ts`: извлечение текстовых пропсов по описанию типа из `registry-props.ts`. Не «все строки подряд» — адрес ссылки и идентификатор файла тоже строки. Один источник на форму редактора и на проверку: новый текстовый проп попадает под стоп-словарь сам.

Тексты собираются из того же набора страниц, что проверяет комплаенс, плюс глобальные области, плюс текст самой полосы риск-предупреждения — он живёт отдельным полем и через обход дерева не проходит.

### 3. Не сделано: дисклеймеры — [[BUG-010]]

Второе правило починить не удалось, и причина записана в самом баге: текстам дисклеймеров в системе негде храниться. Включить правило блокирующим сейчас — значит остановить сборку любой страницы с калькулятором. Требуется модель, а не правка вызова.

## Как проверено

> [!check] Проверка ломает вход той же причиной, от которой защищаемся
> Не выдуманным «пустым списком», а незаполненным полем снапшота — ровно тем состоянием, в котором сборка прожила месяц.

| Проверка | |
|---|---|
| `validators.test.ts` — 8 новых | снапшот с `texts: null` даёт `check-not-executed`; несобранный материал каждого из четырёх ретрансляторов отклоняет свою проверку; сайт без страниц собирается; обещание доходности блокирует |
| `validation.test.ts` — 7 новых | `missing` отклоняет, `empty` не отклоняет, охват виден по каждому валидатору, упавший валидатор считается не выполнившимся, резюме называет невыполненные первой строкой |
| `collect-text.test.ts` — 12 | что считается текстом, вложенные слоты, повторяемые группы, повреждённый вход не роняет сбор |
| `compliance-gate.integration.test.ts` — 4 новых, на живой БД | обещание доходности на опубликованной странице **не даёт собрать релиз**; находка указывает на страницу и блок; черновик сборку не ломает; отчёт показывает, сколько текстов осмотрено |
