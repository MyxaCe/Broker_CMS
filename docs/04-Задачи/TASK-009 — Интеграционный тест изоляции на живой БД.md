# TASK-009 — Интеграционный тест изоляции на живой БД

> [!success] Карточка
> **Статус:** ✅ done `2026-07-31` — 20 тестов против живой базы, прогоняются в CI
> **Пункт ТЗ:** разд. 3, разд. 11 (критерий приёмки) · **Связано:** [[ADR-0012]]

## Описание

Правила изоляции подключены к коллекциям и покрыты модульными тестами. Но модульные тесты проверяют **наш перевод решения в условие выборки**, а не то, как Payload это условие применяет.

Критерий приёмки ТЗ сформулирован как утверждение о поведении системы: «редактор сайта A технически не может прочитать или изменить данные сайта B — доказано автотестом». Доказать это может только тест против работающего приложения с базой.

## Что проверено

`src/platform/tenancy/isolation.integration.test.ts`, 20 тестов против настоящей базы. Все обращения идут с `overrideAccess: false` — то есть проходят ровно тот же путь, что и запрос извне.

**Чтение:**
- [x] выборка списком содержит только свой сайт;
- [x] **запрос по прямому идентификатору** чужого сайта отклоняется — главный сценарий, который пропускает фильтр интерфейса;
- [x] чужой бренд недоступен;
- [x] привязка к региону разворачивается в его сайты и не дальше;
- [x] кросс-тенантная роль видит все шесть тенантов;
- [x] отключённая кросс-тенантная роль получает отказ;
- [x] анонимный запрос получает отказ.

**Изменение:**
- [x] чужой сайт нельзя изменить, удалить; тенанта нельзя создать;
- [x] отдельной проверкой — чужой сайт остался нетронутым после всех попыток.

**Учётные записи:**
- [x] редактор видит только пользователей своего тенанта, чужую карточку по прямому идентификатору не получает;
- [x] редактор правит свою карточку, но **не может повысить себе роль**;
- [x] редактор **не может расширить себе привязку** к тенантам;
- [x] редактор не может завести учётную запись;
- [x] учётная запись без привязки не сохраняется.

**Целостность цепочки:**
- [x] сайт без юрисдикции и бренд с родителем не сохраняются.

## Критерий готовности

- [x] Тест выполняется в CI отдельным заданием с сервисом Postgres и падает при ослаблении любого правила.
- [x] Пункт «изоляция тенантов» в [[Критерии приёмки]] отмечен со ссылкой на этот тест.

> [!important] Что выяснилось по ходу
> **Отказ приходит исключением `Forbidden`, а не пустой выборкой.** Я ожидал, что запрос вернёт ноль записей; на деле Payload отклоняет его до обращения к базе. Это строже ожидаемого, и ожидания в тестах поправлены под фактическое — более безопасное — поведение.
>
> **Тест немедленно нашёл [[BUG-002]]** — дефект, из-за которого коллекция тенантов не читалась вообще. Он существовал с момента её создания и не проявился ни в одной из 141 модульной проверки, потому что ни одна из них не обращалась к базе.
