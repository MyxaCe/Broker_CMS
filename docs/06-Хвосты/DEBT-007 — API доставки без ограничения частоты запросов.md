# DEBT-007 — API доставки без ограничения частоты запросов

> [!warning] Карточка
> **Статус:** open · **Приоритет:** p1 · **Когда платим:** M1, до выкатки наружу
> **Где:** `src/modules/delivery/api` · **Связано:** [[ADR-0019]]

## Как должно быть

Ключ доставки имеет предел частоты запросов (ТЗ разд. 6). Утёкший ключ ограничен в том, что им можно сделать, а один сорвавшийся потребитель не роняет выдачу остальным.

## Как сделано сейчас

Ограничения нет ни на уровне приложения, ни на уровне прокси: каждый запрос доходит до базы и читает канал и релиз.

## Почему так

Ограничение частоты — это состояние, разделяемое между процессами; в памяти одного процесса оно бессмысленно, как только процессов станет два. Настоящая реализация опирается на Redis, который в контуре есть, но к доставке ещё не подключён.

Делать «пока в памяти» я не стал намеренно: такая версия выглядит как защита, не являясь ею, и её оставляют.

## Чем это грозит

> [!danger] Утёкший ключ ничем не ограничен
> Ключ, попавший в чужие руки, работает с любой частотой, пока его не отозвали. Отзыв мгновенный, но заметить утечку без ограничения частоты не по чему: аномальная нагрузка — первый признак.

Второе: каждый запрос доходит до БД, поэтому обычный перебор упирается в базу, а не в счётчик.

## Когда платим

M1, **до того как дверь окажется доступна извне**. Пока API отвечает только в локальном контуре, риска нет — это и есть причина, по которой хвост допустим.

- [ ] предел на ключ, а не на адрес: за одним адресом сидит целый сайт, а ключ у каждого потребителя свой;
- [ ] счётчик в Redis, общий для всех процессов;
- [ ] превышение отвечает `429` с `Retry-After` — и этот ответ тоже проходит схему (значит, в перечень кодов ошибок добавляется `rate-limited`, и это изменение контракта);
- [ ] предел настраивается на ключ: у витрины и у выгрузки в поиск разные профили нагрузки;
- [ ] отдельный предел на **неудачные** авторизации — иначе подбор ключа ограничен так же слабо, как обычное чтение;
- [ ] на прокси ([[ADR-0016]]) стоит грубый предел как второй рубеж: приложение может не подняться, а дверь при этом уже открыта.
