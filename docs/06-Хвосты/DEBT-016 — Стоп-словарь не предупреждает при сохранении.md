# DEBT-016 — Стоп-словарь не предупреждает при сохранении

> [!warning] Карточка
> **Статус:** open · **Приоритет:** p2 · **Когда платим:** M3, вместе с остатком конструктора
> **Где:** `src/modules/design/forbidden-claims.ts` — вызывается только из `validators.ts`
> **Связано:** [[DEBT-013]] — основная часть погашена там

## Как должно быть

ТЗ 2.4: «Стоп-словарь обещаний доходности. **При сохранении — предупреждение**; для контента класса `compliance` — блокировка публикации до аппрува».

Два разных момента и два разных исхода. Предупреждение при сохранении — чтобы редактор увидел проблему, пока помнит, что писал. Блокировка на публикации — чтобы нарушение не уехало.

## Как сделано сейчас

Работает только вторая половина: обещание доходности блокирует **сборку релиза** ([[DEBT-013]] погашен `2026-09-03`). При сохранении страницы не происходит ничего.

Практически это значит, что редактор узнаёт о формулировке не в момент написания, а при попытке выпустить релиз — возможно, через неделю и не он.

## Почему так

Сначала сделана та половина, которая не даёт нарушению уехать наружу. Порядок сознательный: предупреждение, которое можно закрыть, не заменяет отказа, а отказ без предупреждения хотя бы работает.

## Чем это грозит

Не публикацией нарушения — от неё защищает гейт. Стоимостью исправления: страница, собранная из десяти блоков неделю назад, правится дороже, чем строка, которую только что написали. И правит её, скорее всего, не автор.

## Когда платим

M3, вместе с остатком интерфейса конструктора ([[DEBT-011]]): предупреждение показывается там же, где показываются расхождения дерева блоков, — прямо у блока. Отдельный механизм показа заводить незачем.

- [ ] вызов `findForbiddenPhrases` в форме конструктора по тем же полям, что собирает `collectTexts`;
- [ ] предупреждение **не блокирует** сохранение: черновик с неудачной формулировкой — нормальное промежуточное состояние.
