# DEBT-012 — `next dev` переписывает `next-env.d.ts`

> [!warning] Карточка
> **Статус:** open · **Приоритет:** p3 · **Когда платим:** M4 или раньше, при первой правке обвязки
> **Где:** `next-env.d.ts`, `.prettierignore`

## Как должно быть

`pnpm run verify` зелёный локально ⇒ зелёный в CI. Это обещано в README и ради этого `verify` собран из тех же шагов, что и задание CI.

## Как сделано сейчас

`next-env.d.ts` закоммичен в форматировании Prettier (без точки с запятой, одинарные кавычки). `next dev` переписывает его своим:

```diff
-import './.next/dev/types/routes.d.ts'
+import "./.next/dev/types/routes.d.ts";
```

После любого запуска `next dev` рабочее дерево грязное, а `pnpm run format:check` — красный. Лечится `git checkout -- next-env.d.ts` перед каждым прогоном проверок.

В CI дефект не виден: там `next dev` не запускается. Поэтому он и живёт — ломает только локальный цикл.

## Почему так

Файл генерируется фреймворком и помечен в себе же «This file should not be edited», но при этом закоммичен и не внесён в `.prettierignore` — в отличие от `src/payload-types.ts`, для которого ровно эта ловушка уже разобрана и записана в комментарии `.prettierignore`.

## Чем это грозит

Не безопасностью и не данными — дисциплиной. Проверка, которая краснеет от постороннего, приучает к тому, что красный `format:check` можно игнорировать. Дальше в нём тонет настоящее расхождение.

## Когда платим

Одна строка в `.prettierignore`. Не сделано сейчас, чтобы правка обвязки не ехала внутри задачи про развёртывание: `.prettierignore` — общий файл, и его изменение стоит отдельного коммита с объяснением.

## Рядом, тем же классом

`pnpm run format:check` также краснеет на `CLAUDE.md`, если он лежит в корне: файл не в репозитории (инструкция команде), но Prettier его видит. Лечится тем же способом.
