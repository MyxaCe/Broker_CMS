# DEBT-001 — Lock-файл отсутствует

> [!success] Карточка
> **Статус:** ✅ paid `2026-07-29` — прожил около часа
> **Связано:** [[TASK-004]], [[ADR-0007]], [[Q-007]]

## Как должно быть

`pnpm-lock.yaml` закоммичен, CI ставит зависимости с `--frozen-lockfile` — то есть не имеет права молча разрешить версии иначе, чем разработчик локально.

## Как сделано сейчас

`package.json` написан, lock-файла нет: на машине разработчика отсутствуют Node и pnpm ([[Q-007]]), выполнить `pnpm install` невозможно.

CI-воркфлоу уже написан с `--frozen-lockfile` — намеренно, в правильном виде. До появления lock-файла он **упадёт на шаге установки**.

## Почему так

Альтернатива — временно поставить в CI `pnpm install` без `--frozen-lockfile`. Отвергнута: послабление в CI, введённое «на время», переживает причину своего появления. Пусть лучше красный CI честно показывает незавершённость каркаса, чем зелёный скрывает ослабленную проверку.

## Чем это грозит

Ничем, пока репозиторий не подключён к CI: падение будет на первом же прогоне и очевидно по сообщению. Опасность возникает только если кто-то «починит» это ослаблением флага вместо генерации lock-файла.

## Как погашен

`2026-07-29`, после установки тулчейна ([[Q-007]]):

```
pnpm install      → pnpm-lock.yaml создан, 166 пакетов
pnpm run verify   → линтер, формат, типы, 24 теста — зелёные
```

Lock-файл вошёл в первый коммит `7e09f9a`. Флаг `--frozen-lockfile` в CI не ослаблялся ни на минуту — что и было смыслом отказа от временного послабления.
