# Q-007 — Тулчейн на машине разработки

> [!question] Карточка
> **Статус:** 🔴 open · **Приоритет:** p0 · **Задан:** `2026-07-29`
> **Блокирует:** прогон любых проверок, [[DEBT-001]], завершение [[TASK-004]]

## Что обнаружено

На рабочей машине (Windows 11) отсутствуют **Node.js, pnpm и git**. Установлен только Docker CLI (v29.6.1), причём демон не запущен. `winget` доступен (v1.29.280), прав администратора нет.

Следствие: файлы каркаса написаны, но **ни одна проверка не выполнялась** — ни линтер, ни типы, ни тесты. Без git невозможно и версионирование, которого требует ТЗ разд. 8.

## Варианты и их цена

| Вариант | Что это значит | Цена |
|---|---|---|
| **Локальная установка** — Node LTS + pnpm + Git | обычная разработка: тесты и линтер запускаются мгновенно, IDE видит типы | нужна установка ПО; без прав администратора — user-scope или portable-сборки |
| **Всё в Docker** — тулчейн только внутри контейнера | ничего не ставится в систему, среда идентична CI | каждый прогон тестов идёт через контейнер (медленнее); IDE не видит `node_modules` без дополнительной настройки; git всё равно нужен снаружи |
| **Разработка на VPS** — код и тулчейн на сервере | всё окружение уже там | правки по SSH, нет локальной IDE, риск задеть тестовый контур |

## Рекомендация

> [!tip] Мнение архитектора
> **Локальная установка Node LTS, pnpm и Git.** Docker остаётся для инфраструктуры (Postgres, Redis, S3-совместимое хранилище), но тулчейн должен быть под рукой: цикл «правка → тест» выполняется десятки раз в час, и лишние секунды на контейнер каждый раз — это не про удобство, а про то, будут ли тесты запускаться вообще.
>
> Без прав администратора всё ставится в пользовательский профиль: `winget install --scope user OpenJS.NodeJS.LTS`, pnpm включается через `corepack enable`, Git — portable-сборкой или user-scope установщиком. Всё обратимо удалением каталога.
>
> Git нужен в любом варианте: без него нет ни версионирования, ни CI, чего ТЗ разд. 8 требует прямо.
