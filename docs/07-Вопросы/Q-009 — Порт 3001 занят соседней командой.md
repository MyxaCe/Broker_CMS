# Q-009 — Порт 3001 занят соседней командой

> [!question] Карточка
> **Статус:** open · **Приоритет:** p2 · **Кому:** штаб / команда витрины

## Вопрос

`pnpm run dev` не поднимается: порт `3001` занят.

```
⨯ Failed to start server
Error: listen EADDRINUSE: address already in use :::3001
```

Занимает его не наш процесс, а dev-сервер витрины:

```
node .../Broker/site-platform/apps/web/node_modules/.bin/../next/dist/bin/next dev
→ next/dist/server/lib/start-server.js, слушает 3001
```

Машина разработки одна на пять команд, и `3001` записан в наших умолчаниях трижды: в скриптах `dev` и `start`, в `APP_PUBLIC_URL` и в `.env.example`. У витрины он, судя по всему, записан так же.

## Почему это не решается «просто выбрать другой порт»

Выбрать можно — админка на время проверки поднималась на `3011`, всё работало. Но это решение на одну сессию: следующий, кто выполнит `pnpm run dev` по README, получит тот же отказ, и диагностировать его будет заново.

Смещение портов у нас уже применено осознанно — в `docker-compose.dev.yml` (Postgres `5433`, Redis `6380`, RabbitMQ `5673`), ровно с этим объяснением: «молчаливый конфликт портов диагностируется хуже, чем явное отличие». К порту приложения то же рассуждение не применили — на момент написания конкурента не было.

## Варианты

1. **Занять порт за одной командой явно** — то есть штаб ведёт распределение портов приложений на общей машине наравне со списками вебхуков и ключей. Тогда `3001` остаётся у того, за кем закреплён, а второй переезжает и правит умолчания.
2. **Смещать порты приложений так же, как порты инфраструктуры.** Нам, например, `3021`. Дешевле в исполнении, но правит README, `.env.example` и скрипты — и, значит, требует записи, иначе снова разъедется.
3. Ничего не менять и договариваться каждый раз голосом. Отвергается по той же причине, по которой смещены порты БД.

## Что нужно от штаба

Решение, за кем `3001`, и — если не за нами — новый номер. Правку умолчаний сделаем сами.

> [!note] Границы наблюдения
> Наблюдение сделано на этой машине `2026-09-03`. Про то, как порты распределены на контуре, отсюда судить нельзя — это отдельный вопрос ([[Q-005]]).
