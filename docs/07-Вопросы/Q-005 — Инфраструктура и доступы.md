# Q-005 — Инфраструктура: доступы, версии, среда деплоя

> [!info] Карточка
> **Статус:** 🟠 частично закрыт обследованием `2026-07-28` · **Приоритет:** p1

> Фактическое состояние контура: [[Окружение платформы]]

## Закрыто обследованием тестового VPS

- [x] **Postgres** — 16-alpine в docker, отдельная БД `broker_cms` уже есть.
- [x] **RabbitMQ** — 3.13, vhost `platform`, exchange `platform.events` (topic) + `platform.dlx`, очередь `platform.dlq`. **Учётка `cms` заведена**, права `^(platform\.events|cms\..*)$` — публикация и объявление своих очередей доступны.
- [x] **MDS** — `GET /v1/instruments`, 481 инструмент, форма записи известна. Аутентификации на чтение нет, метрики под токеном. Штатно бывает `degraded` при исчерпании бюджета внешнего провайдера.
- [x] **GlitchTip** — развёрнут, DSN раздельные для web и bff.
- [x] **Среда деплоя (тест)** — Docker Compose + Portainer, каталог `/opt/site-web/deploy`.

## Остаётся выяснить

- [ ] **S3-совместимое хранилище** — чего сейчас нет вовсе: медиа лежит в docker-volume. Какое хранилище используем, есть ли CDN.
- [ ] **Отдельный домен для раздачи пользовательских файлов** — требование ТЗ 5.3.
- [ ] **Redis** — в контуре отсутствует, нужен для кеша выдачи и rate limit (ТЗ разд. 9). Поднимаем сами или есть общий?
- [ ] **Хранение секретов** — сейчас всё в `deploy/.env` открытым текстом. Есть ли vault, или проектируем envelope-шифрование.
- [ ] **Reverse-proxy и HTTPS** — сейчас сервисы торчат портами наружу по HTTP, админка доступна снаружи. Для прода ТЗ разд. 6 требует обратного.
- [ ] **Продовый контур** — где, кто владеет, чем отличается от тестового.
- [ ] **CI** — GitHub Actions уже используются соседними репозиториями; подтвердить, что нам туда же.
- [ ] **Бэкапы** — существующая практика и процедура проверки восстановления (ТЗ разд. 6).

## Рекомендация

> [!tip] Мнение архитектора
> Ответ нужен до [[TASK-004]], но не блокирует проектирование. Отдельно подсвечу два пункта, которые чаще всего оказываются сюрпризом на поздних этапах:
> - **отдельный домен для раздачи пользовательских файлов** — это требование безопасности, а не удобства; его добавление задним числом ломает все существующие ссылки на медиа;
> - **хранилище секретов** — если vault-а нет, envelope-шифрование придётся проектировать в M0, а не «когда дойдём до вебхуков».
