# ⚙️ Конвенции разработки

> [!note] Статус: заготовка
> Наполняется по мере появления кода ([[TASK-004]]). Каждая новая договорённость фиксируется здесь **в момент принятия**, а не «когда устаканится».

---

## Уже действует

1. **Документация обновляется вместе с изменением**, по чек-листу [[Регламент документации#2. Чек-лист после каждого изменения]]. Изменение без записи не считается сделанным.
2. **Хвост в коде помечается** комментарием `// TODO(DEBT-XXX): причина` и одновременно заметкой в [[Хвосты (индекс)]]. Одностороннее упоминание запрещено — хвост должен находиться из обеих сторон.
3. **Даты — только абсолютные**, формат `YYYY-MM-DD`.

---

## Подлежит заполнению

- [ ] **Язык и именование** — язык кода и комментариев, именование коллекций, полей, эндпоинтов, событий.
- [ ] **Структура файлов внутри модуля** — где живут коллекции, хуки, сервисы, схемы, тесты.
- [ ] **Границы модулей** — что считается публичным интерфейсом, как это принуждается технически (eslint-правило / project references).
- [ ] **Работа со схемами** — где канон (`src/contracts/`), как генерируются типы, как обновляются фикстуры.
- [ ] **Миграции БД** — именование, порядок, откат, запрет dev-push.
- [ ] **Тесты** — структура и именование; обязательные уровни по ТЗ разд. 8: unit, контрактные, доступ, интеграционные, негативные, миграции, E2E, нагрузочные.
- [ ] **Git** — ветки, формат коммитов, требования к PR, чек-лист ревью (включая пункты документации).
- [ ] **Логи и ошибки** — формат pino-логов, обязательные поля (`request-id`, `site`, `actor`), что нельзя логировать (секреты, PII).
