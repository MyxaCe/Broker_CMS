## Уже действует

1. **Документация обновляется вместе с изменением**, по чек-листу [[Регламент документации#2. Чек-лист после каждого изменения]]. Изменение без записи не считается сделанным.
2. **Хвост в коде помечается** комментарием `// TODO(DEBT-XXX): причина` и одновременно заметкой в [[Хвосты (индекс)]]. Одностороннее упоминание запрещено — хвост должен находиться из обеих сторон.
3. **Даты — только абсолютные**, формат `YYYY-MM-DD`.
4. **Перед коммитом — `pnpm run verify`.** Он прогоняет ровно то же, что CI: линтер, формат, типы, тесты.

## Локальный контур

Инфраструктура поднимается в Docker, приложение запускается на машине — чтобы цикл «правка → тест» не проходил через сборку образа.

```bash
docker compose -f docker-compose.dev.yml up -d     # Postgres, Redis, RabbitMQ, MinIO
cp .env.example .env                                # значения уже совпадают с compose
pnpm run migrate                                    # применить миграции
```

Порты смещены относительно стандартных (Postgres `5433`, Redis `6380`, RabbitMQ `5673`): на машине может стоять своё, а молчаливый конфликт портов диагностируется хуже, чем явное отличие.

`docker compose -f docker-compose.dev.yml down -v` — остановить и стереть данные.

## Миграции схемы

> [!important] Только миграции, никогда dev-push
> `push: false` в конфигурации Payload — на **любой** БД, включая локальную (ТЗ разд. 13). Иначе схема у разработчика и в проде расходится незаметно, а миграция, которую никто не прогонял локально, впервые исполняется на бою.

```bash
pnpm run migrate:create <имя>   # создать
pnpm run migrate                # применить
pnpm run migrate:status         # что применено
```

`migrate:create` автоматически прогоняет `scripts/normalize-migrations.mjs`: генератор Payload выдаёт файл, который не проходит наши проверки — типы импортируются как значения, а в сигнатуре остаются неиспользуемые параметры. Подробно и с причиной — [[BUG-001]].

Руками сгенерированный файл править не нужно. Если после `migrate:create` линтер всё же ругается на миграцию — значит шаблон Payload изменился и скрипт перестал совпадать; это повод обновить скрипт, а не файл.

## Подлежит заполнению

- [ ] **Язык и именование** — язык кода и комментариев, именование коллекций, полей, эндпоинтов, событий.
- [ ] **Структура файлов внутри модуля** — где живут коллекции, хуки, сервисы, схемы, тесты.
- [ ] **Границы модулей** — что считается публичным интерфейсом, как это принуждается технически (eslint-правило / project references).
- [ ] **Работа со схемами** — где канон (`src/contracts/`), как генерируются типы, как обновляются фикстуры.
- [ ] **Миграции БД** — именование, порядок, откат, запрет dev-push.
- [ ] **Тесты** — структура и именование; обязательные уровни по ТЗ разд. 8: unit, контрактные, доступ, интеграционные, негативные, миграции, E2E, нагрузочные.
- [ ] **Git** — ветки, формат коммитов, требования к PR, чек-лист ревью (включая пункты документации).
- [ ] **Логи и ошибки** — формат pino-логов, обязательные поля (`request-id`, `site`, `actor`), что нельзя логировать (секреты, PII).
