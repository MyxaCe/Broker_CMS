# ADR-0016 — Инфраструктурные решения

> [!success] Статус: ✅ accepted `2026-08-03` — согласовано заказчиком целиком

## Контекст

[[Q-005]] висел с начала проекта: в контуре нет ни объектного хранилища, ни хранилища секретов, ни обратного прокси, ни HTTPS. На разработку это не влияло, но к выкатке — а она назначена на границу M0→M1 — упирается всё сразу.

Отдельное обстоятельство, которое меняет часть обычных ответов: **репозиторий публичный** ([[Q-008]]).

## Решение

### 1. Обратный прокси — Caddy, три домена

| Домен | Куда | Доступ |
|---|---|---|
| `api.<домен>` | приложение, только `/v1` | публично |
| `cms.<домен>` | админка и её служебный HTTP-слой | ограничен списком адресов или VPN |
| `media.<домен>` | объектное хранилище | публично, только чтение |

Caddy получает и продлевает сертификаты сам. Это же закрывает остаток [[TASK-006]]: периметр админки — правило прокси, а не приложения, и наконец появляется рубеж, которого не хватало.

### 2. Отдельный домен для медиа

`media.<домен>`. Требование ТЗ 5.3 и вопрос безопасности, а не удобства: загруженный файл не должен исполняться в origin админки. Условие уже проверяется валидацией окружения — контур нельзя поднять «неправильно» незаметно.

Задним числом это не добавить: смена домена ломает все существующие ссылки на медиа.

### 3. Объектное хранилище — MinIO сейчас, S3 провайдера потом

MinIO уже поднят в локальном контуре и ставится на сервер тем же образом. Для прода — S3-совместимое хранилище **у того же провайдера, где стоит прод**: иначе трафик медиа ходит между площадками, и за него платят дважды.

### 4. Секреты — файлом на сервере, не в репозитории

> [!danger] Почему обычный ответ здесь не работает
> Стандартное удобное решение — SOPS-шифрование прямо в репозитории. При публичном репозитории оно **отпадает**: зашифрованный файл секретов, доступный всем, — это готовый материал для офлайн-подбора. Шифрование защищает от чтения, но не от того, что файл у атакующего уже есть.

Шаги:
1. **Сейчас:** `.env` на сервере, права `600`, владелец — пользователь сервиса. В git не попадает.
2. **К прому:** менеджер секретов (Doppler, Infisical, Vault). Приложение читает при старте, `.env` исчезает.

Разница между шагами не в шифровании, а в ротации и в том, кто видел значение. Пока команда маленькая, шаг 1 честнее, чем видимость защиты.

### 5. Прод — отдельная машина, тот же Docker Compose

Kubernetes при одном сервисе — инфраструктура, которую обслуживают вместо разработки. Compose даёт то же самое и переезжает в K8s позже без переписывания приложения.

**Обязательно отдельная машина**, а не тот же VPS: тестовый контур перезапускают и ломают, и делать это рядом с продом нельзя.

### 6. Выкатка — GitHub Actions по SSH, только с `main`

Сборка образа в Actions, затем `docker compose pull && up -d` по SSH. Ключ деплоя — в секретах репозитория.

> [!warning] Следствие публичности репозитория
> Воркфлоу выкатки запускается **только с ветки `main` и только вручную или по тегу**. Иначе внешний pull request сможет спровоцировать выкатку — а pull request в публичный репозиторий может открыть кто угодно.

### 7. Бэкапы — ежедневный дамп и ежемесячная проверка восстановления

ТЗ разд. 6 требует не только бэкапов, но и процедуры проверки. `pg_dump` раз в сутки в объектное хранилище, хранение 30 дней; раз в месяц — восстановление в пустую базу с прогоном интеграционных тестов против неё.

**Бэкап, который ни разу не восстанавливали, — это предположение, а не бэкап.** Прогон тестов против восстановленной базы проверяет не факт наличия файла, а пригодность данных.

### 8. Роли БД — приложение без прав на схему

Приложение работает ролью без `CREATE`, `ALTER`, `DROP`. Миграции выполняются отдельной ролью.

Дополнительный рубеж к триггерам неизменяемости из [[ADR-0014]], а не замена: триггер действует независимо от прав, права действуют независимо от триггера.

## Альтернативы

- **nginx + certbot вместо Caddy.** Привычнее, но продление сертификатов становится отдельным механизмом, который ломается молча — а истёкший сертификат на сайте брокера это инцидент.
- **SOPS или age в репозитории.** Отвергнуто из-за публичности, см. п. 4.
- **Kubernetes сразу.** Отвергнуто: один сервис не окупает обслуживание кластера.
- **Прод на том же VPS.** Отвергнуто: тестовый контур существует ради того, чтобы его ломать.
- **Автоматическая выкатка на каждый push в `main`.** Отвергнуто на текущем этапе: пока нет ни блокирующих проверок на выкатке, ни стенда для прогрева, ручной запуск честнее.

## Последствия

- ✅ [[Q-005]] закрыт в части решений; остались только данные — доменные имена и владелец инфраструктуры.
- ✅ Периметр админки получает механизм — остаток [[TASK-006]] перестаёт быть «непонятно чем».
- ✅ Требование ТЗ о проверяемых бэкапах становится процедурой, а не пунктом.
- ❌ Секреты в файле означают, что их видел каждый, у кого есть доступ к серверу, и ротация выполняется руками. Это осознанный шаг 1, а не конечное состояние.
- ❌ Ручная выкатка означает, что кто-то должен её запускать. При росте частоты релизов это станет узким местом — тогда и появятся автоматические условия.
- 🔁 Пересмотреть при появлении второго сервиса (тогда K8s начинает окупаться) и при передаче системы редакторам (тогда нужен менеджер секретов).
