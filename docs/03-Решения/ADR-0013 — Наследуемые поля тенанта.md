# ADR-0013 — Наследуемые поля тенанта

> [!success] Статус: ✅ accepted `2026-07-31`

## Контекст

[[ADR-0010]] описал механизм наследования и покрыл его тестами, но **ни одно поле его не использовало**: резолвер существовал сам по себе. Чем дольше так, тем выше риск, что к M3 протестированное и работающее разойдутся.

Первыми наследуемыми полями выбраны те, что уже существуют и осмысленны на всех уровнях цепочки: **юрисдикция**, **перечень локалей**, **локаль по умолчанию**. Токены, библиотека блоков и правовой каркас появятся на M3–M4 и лягут на тот же механизм.

## Решение

### 1. Режим — отдельное поле, а не следствие заполненности

Каждое наследуемое поле хранится группой:

```
jurisdiction: { mode: inherit | override | fork, value }
availableLocales: { mode: inherit | extend | fork, items[] }
```

Соблазн вывести режим из данных («значение есть — значит переопределено») выглядит проще, но теряет главное: **`override` и `fork` неразличимы по значению**. Это разные решения редактора, и в аудите они обязаны выглядеть по-разному — иначе невозможно ответить, почему сайт перестал получать обновления от бренда ([[ADR-0010]]).

### 2. Режим без значения не перекрывает родителя пустотой

`override` или `fork` с пустым значением трактуется как `inherit`. Редактор, выбравший режим и не заполнивший поле, почти наверняка не закончил, а не выразил намерение стереть унаследованное.

Для **коллекций** правило обратное: пустой список при явном режиме сохраняется. «Отвязаться и не наследовать ничего» — осмысленное состояние, в отличие от пустой строки.

### 3. Обязательность проверяется на РАЗРЕШЁННОМ значении

Ключевое изменение относительно первой версии. Раньше сайт был обязан задать юрисдикцию **сам** — что отменяло наследование ровно для того поля, ради которого оно в первую очередь и нужно.

Теперь: сайт обязан иметь юрисдикцию **свою или унаследованную**. Требование fail-closed из [[ADR-0003]] сохранено полностью — сайт, у которого юрисдикции нет нигде в цепочке, не сохраняется, — но перестало противоречить модели.

Соответственно правила разделились:

| Где | Что проверяет |
|---|---|
| `validateTenantDraft` | по одному документу: slug, соответствие уровня и родителя |
| `validateResolvedSettings` | по всей цепочке: юрисдикция, локали, локаль по умолчанию |

### 4. Сохранение тенанта проверяет всю ветку над ним

Чтобы разрешить значения, надо построить цепочку — а `buildChain` попутно отвергает циклы, лишнюю глубину и недопустимый порядок уровней. Проверка структуры досталась бесплатно и работает при каждом сохранении.

### 5. Отдельная функция для разрешения по идентификатору

`resolveTenantById` читает лист из базы целиком. Причина прикладная: передать в резолвер «почти документ» — распространённая ошибка, при которой собственные значения листа теряются, и результат выглядит полностью унаследованным. **Я допустил её сразу же**, в первом варианте интеграционного теста, и тест это поймал.

## Альтернативы

- **Выводить режим из заполненности значения.** Отвергнуто: см. п. 1. Экономит одно поле в интерфейсе ценой невозможности отличить переопределение от отвязки.
- **Оставить юрисдикцию обязательной локально.** Отвергнуто: прямо противоречит наследованию и заставляет дублировать одно и то же значение на каждом сайте региона — то есть гарантирует расхождение при первом же его изменении.
- **Денормализовать разрешённые значения в карточку сайта** (хранить готовый результат). Отвергнуто: чтение стало бы быстрее, но изменение бренда перестало бы доезжать до сайтов без пересчёта. Интеграционный тест специально проверяет, что правка региона немедленно видна сайту, который её наследует.
- **Разрешать значения только на сборке релиза.** Отвергнуто: тогда ошибка обнаруживается при публикации, а не при сохранении. Дешевле отказать редактору сразу.

## Последствия

- ✅ Механизм наследования перестал быть «написанным, но неиспользуемым»: три поля работают через него, и это проверено сквозь базу.
- ✅ Требование fail-closed по юрисдикции сохранено и при этом совместимо с наследованием.
- ✅ Структура цепочки проверяется при каждом сохранении тенанта.
- ✅ Правка региона доезжает до наследующих сайтов немедленно — отдельный интеграционный тест.
- ❌ Разрешение значений требует чтения всех предков. На цепочке максимум в три звена это два дополнительных запроса; при росте числа полей понадобится кеш цепочки на запрос.
- ❌ Интерфейс поля стал сложнее: вместо одного поля — группа из режима и значения. Это цена различимости `override` и `fork`, и она осознанная.
- 🔁 Пересмотреть при добавлении токенов и библиотеки блоков (M3): там объём наследуемых данных на порядок больше, и стоимость чтения предков придётся измерить.
