# ADR-0008 — Версии стека

> [!success] Статус: ✅ accepted `2026-07-29`

## Контекст

ТЗ разд. 9 задаёт стек, но версии описывает словами: «Payload 3 (актуальная стабильная)», «Next.js 15», «React 19». [[ADR-0007]] отложил объявление фреймворковых зависимостей до момента, когда дерево можно реально разрешить. Тулчейн установлен — момент настал.

Версии выбраны **по фактическому состоянию реестра и заявленным peer-диапазонам**, а не по памяти и не по тому, что стоит у соседней команды.

## Решение

| Пакет | Версия | Способ закрепления |
|---|---|---|
| `payload` и `@payloadcms/*` | **3.86.0** | точная |
| `next` | **16.2.12** | точная |
| `react`, `react-dom` | **19.2.8** | точная |
| `graphql` | `^16.8.1` → 16.14.2 | диапазон |
| `sharp` | **0.35.3** | точная |
| Node | **>=22.11**, проверено на 24.18 LTS | `engines` |
| pnpm | **9.15.9** | поле `packageManager` |

**Фреймворковый набор закрепляется точными версиями**, инструменты разработки — диапазонами. Причина: расхождение версий внутри связки Payload/Next/React ломается не на этапе установки, а в рантайме, и диагностируется хуже всего.

**Проверенные факты, а не предположения:**

- `payload@3.86.0` — актуальная стабильная в реестре на `2026-07-29`.
- `@payloadcms/next@3.86.0` объявляет peer-диапазон `next: >=15.2.9 <15.3.0 || >=15.3.9 <15.4.0 || >=15.4.11 <15.5.0 || >=16.2.6 <17.0.0` — то есть **Next 16 поддерживается официально**.
- `graphql` требуется в диапазоне `^16.8.1`, поэтому вышедший 17.x **не берём**, хотя он и новее. Пакет остаётся в зависимостях как peer, несмотря на отключённый GraphQL — без него Payload не соберётся.
- Payload заявляет `engines: node ^18.20.2 || >=20.9.0`; наш нижний порог выше (`>=22.11`), потому что Node 20 вышел из поддержки.

## Альтернативы

- **Next 15.4.11 — версия, работающая у соседней команды.** Отвергнуто: это выбор «как у них», а не по существу. Payload официально поддерживает Next 16, а начинать новый проект на предыдущей мажорной ветке — значит запланировать миграцию на ближайшие месяцы. Совпадение стека с существующей CMS не является целью: код не переиспользуется ([[ADR-0006]]), а версии — не код.
- **`graphql@17`** — отвергнуто: вне peer-диапазона Payload. Новее ≠ совместимее.
- **Диапазоны `^` для фреймворкового набора** — отвергнуто: минорное обновление Payload или Next, приехавшее незаметно, ломает связку в рантайме. Обновление должно быть событием с прогоном контрактных тестов, что и настроено в `renovate.json`.
- **Node 20 LTS** — отвергнуто: вне поддержки на дату решения.

## Последствия

- ✅ Версии выбраны по объявленным диапазонам совместимости, проверяемым командой `pnpm view`, а не по памяти.
- ✅ Локальная среда и CI используют одну мажорную версию Node — расхождение «у меня работает» исключено.
- ✅ Обновление фреймворка требует явного действия и прогона тестов.
- ❌ Точные версии означают ручное обновление даже для патчей безопасности внутри связки. Смягчается `vulnerabilityAlerts` в Renovate, который создаёт PR немедленно.
- ❌ `graphql` остаётся в зависимостях, хотя GraphQL отключён — вес без пользы. Это требование Payload, а не наш выбор.
- 🔁 Пересмотреть при выходе Payload 4 или при смене минимальной поддерживаемой версии Node.
