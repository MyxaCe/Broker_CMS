# ADR-0001 — Структура и регламент проектной документации

> [!info] Карточка
> **Статус:** ✅ accepted · **Область:** процесс · **Дата:** 2026-07-28
> **Пункт ТЗ:** — (прямой запрос заказчика) · **Связано:** [[ADR-0002]], [[TASK-001]]

## Контекст

Проект большой (13 разделов ТЗ, 6 этапов M0–M6, регулируемый домен), рассчитан на долгую работу с неизбежной потерей контекста между сессиями. Без внешней памяти решения будут переприниматься, хвосты — забываться, а отступления от ТЗ — теряться молча. Заказчик явно потребовал вести документацию, куда пишутся решения, баги, хвосты и задачи, и обновлять её после каждого изменения.

Дополнительное требование заказчика (2026-07-28): документация должна быть адаптирована под Obsidian.

## Решение

Каталог `docs/` — корень волта Obsidian со структурой:

- **одна сущность — одна заметка** (ADR, задача, баг, хвост, вопрос), связи через wikilinks;
- сквозные ID (`ADR-`, `TASK-`, `BUG-`, `DEBT-`, `Q-`), продублированные в `aliases` frontmatter, чтобы работала короткая ссылка `[[TASK-001]]`;
- frontmatter с `status` / `priority` / `stage` + зеркальные теги — первое для Dataview-таблиц, второе для поиска и графа;
- индексные заметки-MOC с Dataview-запросами вместо ручных списков;
- нумерованные папки (`00-source`, `01-Регламент`, …) для порядка в сайдбаре;
- шаблоны заметок в `01-Регламент/Шаблоны/`.

Регламент ведения зафиксирован в [[Регламент документации]] и обязателен.

## Альтернативы

- **Один файл `NOTES.md`** — отвергнуто: при объёме этого ТЗ станет нечитаемым за две недели, поиск невозможен, конфликты при правках.
- **Плоские журналы-файлы** (`DECISIONS.md`, `TASKS.md` со списками внутри) — первоначально сделано именно так, затем отвергнуто: в Obsidian сущность внутри файла не имеет обратных ссылок, не попадает в граф и не индексируется Dataview. Связь «Q-002 блокирует TASK-002, породил ADR-0003» существует только текстом, а не как проверяемая ссылка.
- **GitHub Issues / внешний трекер** — отвергнуто на старте: репозиторий не инициализирован, трекера нет, документация должна быть доступна без сети и жить рядом с кодом. Возможен перенос позже.
- **Только `CLAUDE.md`** — отвергнуто: это файл инструкций для агента, а не журнал проекта; смешивать роли вредно.

## Последствия

- ✅ Восстановление контекста в новой сессии — за одно чтение [[README]].
- ✅ Ответ на «почему так сделано» без археологии по коду.
- ✅ Граф связей показывает, что чем заблокировано, без ручного трекинга.
- ❌ Много мелких файлов — навигация без Obsidian (например, через веб-интерфейс git) менее удобна, чем по одному файлу.
- ❌ Накладные расходы на каждое изменение: сначала запись, потом код.
- ❌ Индексы зависят от плагина Dataview; без него видны только ручные списки — поэтому ручные списки в индексах сохраняются как запасной вариант.
- 🔁 Пересмотреть, если проект переедет в полноценный трекер задач с интеграцией в CI.
