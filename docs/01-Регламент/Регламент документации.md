# 📏 Регламент документации

> [!important] Статус
> Обязателен к исполнению. Зафиксирован решением [[ADR-0001]]. Изменяется только новым ADR.

---

## 1. Принципы

1. **Документация — часть работы, а не отчёт о ней.** Изменение не считается сделанным, пока не записано.
2. **Пишем сразу.** Решение принято → в тот же момент ADR. Хвост оставлен → в тот же момент [[Хвосты (индекс)|DEBT]]. «Допишу в конце» = не допишу.
3. **Максимальная подробность.** Записываем не только *что*, но и *почему*, *какие альтернативы отвергли* и *чем платим*.
4. **Ничего не удаляем.** Закрытая задача, исправленный баг, отменённое решение — меняют `status` во frontmatter, но остаются в волте. История решений — такой же артефакт, как код.
5. **Один факт — одно место.** Дублирование запрещено. Вместо копии — `[[wikilink]]`.
6. **ТЗ — канон.** [[ТЗ — исходный промт]] не редактируется никогда. Любое отступление — ADR со статусом «Отступление от ТЗ» и явное согласие заказчика.

---

## 2. Чек-лист после каждого изменения

> [!check] Выполнять целиком, каждый раз
> - [ ] Заметка задачи ([[Задачи (индекс)|TASK-XXX]]) переведена в актуальный `status`, дописан **Лог**.
> - [ ] Принято решение (библиотека, схема, подход) → создан [[Решения (индекс)|ADR-XXXX]].
> - [ ] Что-то сделано «пока так» / с заглушкой → создан [[Хвосты (индекс)|DEBT-XXX]] **и** проставлен `// TODO(DEBT-XXX)` в коде.
> - [ ] Найден баг — любой, даже не наш → создан [[Баги (индекс)|BUG-XXX]].
> - [ ] Вылезла неопределённость → создан [[Вопросы (индекс)|Q-XXX]].
> - [ ] В конце сессии → запись в [[Журнал (индекс)]].

---

## 3. Как заводить новую заметку

1. Копируем нужный шаблон из `01-Регламент/Шаблоны/` (или вставляем через плагин Templates).
2. Кладём в свою папку: решения → `03-Решения/`, задачи → `04-Задачи/` и т. д.
3. Имя файла: `TASK-007 — Короткое название.md`.
4. Во frontmatter обязательно `aliases: [TASK-007]` — иначе не сработает короткая ссылка `[[TASK-007]]`.
5. Проставляем `status`, `priority`, `stage`, `created`, `updated`, теги.
6. Связываем: у задачи ставим ссылки на вопрос, который её блокирует, и на решение, которое её породило. **Связь ставится с обеих сторон** — обратные ссылки Obsidian покажут вторую сторону автоматически, но явная ссылка читается лучше.

## 4. Идентификаторы

ID сквозные и **никогда не переиспользуются** — даже если сущность отменена.

| Префикс | Сущность | Папка |
|---|---|---|
| `ADR-0001` | архитектурное решение | `03-Решения/` |
| `TASK-001` | задача | `04-Задачи/` |
| `BUG-001` | баг | `05-Баги/` |
| `DEBT-001` | технический хвост | `06-Хвосты/` |
| `Q-001` | открытый вопрос | `07-Вопросы/` |

---

## 5. Статусы

| Сущность | Жизненный цикл |
|---|---|
| Задача | `backlog` → `planned` → `in-progress` → `blocked` → `review` → `done` / `cancelled` |
| Решение | `proposed` → `accepted` → `superseded` / `rejected` |
| Баг | `open` → `in-progress` → `fixed` → `verified` / `wontfix` |
| Хвост | `open` → `paid` / `accepted-permanently` |
| Вопрос | `open` → `answered` → `closed` / `assumed` |

**Приоритеты:** `p0` блокер или регуляторный риск · `p1` критично для этапа · `p2` нужно · `p3` желательно.

**Даты:** только абсолютные, формат `YYYY-MM-DD`. Никаких «вчера» и «на прошлой неделе».

---

## 6. Frontmatter — минимальный набор

```yaml
---
title: TASK-007 — Название задачи
aliases: [TASK-007]
type: task            # adr | task | bug | debt | question | spec | log | meta
status: planned
priority: p1
stage: M1
created: 2026-07-28
updated: 2026-07-28
related: ["[[Q-002]]", "[[ADR-0003]]"]
tags: [task, status/planned, p1, stage/M1, area/delivery]
---
```

> [!warning] Теги дублируют frontmatter намеренно
> Поля `status`/`priority` нужны Dataview для таблиц и сортировки, теги — для быстрого поиска и графа. При смене статуса меняем **и то, и другое**.
