## Поправка заказчика: пишем с нуля

После первой версии выводов по обследованию заказчик поправил формулировку — и поправка существенная, зафиксирована как [[ADR-0006]]:

> **CMS переписывается полностью. Из существующего сервиса не берётся ни байта кода.**
> Основание: другая команда нашла в работающей на проде CMS **более 40 ошибок**; сервис невелик, чинить накопленное дороже и менее предсказуемо, чем построить заново. Решение принято не с потолка и не подлежит пересмотру «ради экономии».

Что исправлено в документации:
- убраны формулировки «унаследуем», «переиспользуется, а не пишется заново», «миграция — эволюция»;
- раздел [[Окружение платформы#4. Текущая CMS — только как источник данных для миграции]] переписан: старый сервис релевантен только как источник **данных** для миграции и как описание legacy-контракта для переходного адаптера;
- дефекты текущего контура переформулированы из «что починить» в **negative-требования** — что новая система обязана сделать невозможным по конструкции;
- явно зафиксировано: старые JSON Schema **не годятся** как основа `src/contracts/` — они описывают модель из 14 плоских ресурсов, а новая модель блочная, релизная, с наследованием и измерениями.

**Второе правило из той же поправки:**

> **Проектируем под горизонт ТЗ, а не под сегодняшний факт.** 481 инструмент вместо 2000+, один сайт, одна языковая пара — это снимок момента. Требования к модели, UI и производительности берутся из ТЗ. Замеры контура нужны для планирования, но планку не понижают.

[[Параметры внедрения]] возвращены к значениям ТЗ, [[Схема сервисов]] дополнена, заведена [[TASK-008]] — получить перечень 40+ дефектов и превратить в проверяемый чек-лист.
