**Две проверки предметной области** реализованы прямо в схеме окружения — они превращают принятые решения в исполняемый код:

- `TRADING_TERMS_MODE` **без умолчания** — оказаться в ослабленном режиме `unverified` случайно невозможно ([[ADR-0005]]);
- `MEDIA_PUBLIC_URL` обязан отличаться по origin от `APP_PUBLIC_URL` — совпадение означает XSS через загрузку файла (ТЗ 5.3). Раньше это был пункт в [[Q-005]], теперь — отказ старта.

## Решения

| ADR | Решение |
|---|---|
| [[ADR-0007]] | Границы модулей принуждаются ESLint `no-restricted-imports` по зонам; правила покрыты тестами; состав зависимостей на M0 минимален |

Отвергнуты с обоснованием: `dependency-cruiser` (лишний инструмент на текущем объёме правил), TypeScript project references (усложняют сборку, пока структура уточняется — кандидат на момент выделения `delivery`), объявление всего целевого стека сразу (зафиксировало бы непроверенные версии).

## Тулчейн: обнаружено и решено в тот же день

На машине не оказалось **Node, pnpm и git** — только Docker CLI с незапущенным демоном. Заведён [[Q-007]]; заказчик выбрал локальную установку и поручил её выполнить.

Установлено через `winget` без прав администратора: **Node 24.18.0 LTS**, npm 11.16.0, corepack 0.35.0, **pnpm 9.15.9** (через `corepack enable`), **Git 2.55.0.3**.

Три уточнения по факту:
- Node LTS оказался 24.x, а не 20.x — **Node 20 вышел из поддержки**. `engines` подняты до `>=22.11`, версия в CI выровнена на 24: расхождение локальной и CI-среды — источник ошибок вида «у меня работает».
- Идентичность git настроена локально для репозитория, глобальный конфиг не тронут.
- **`core.autocrlf` собирался нормализовать переносы строк в каноне ТЗ.** Это сломало бы побайтовую неизменность из [[ADR-0002]] — то самое свойство, ради которого канон и заведён. Закрыто `.gitattributes` с `-text` на файл канона.
